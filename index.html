HSI-202

Bug report: stuck button

practice

A sample report showing how I describe a problem so a developer can reproduce it quickly.

Open bug report

Title: "Place order" stays disabled after fixing a form error

Severity: Medium   Priority: High

Steps to reproduce

  1. Add any plant to the cart and go to checkout.
  2. Leave the phone number empty and tap Place order. An error appears.
  3. Enter a valid phone number.

Expected: The error clears and Place order becomes active.

Actual: The error clears, but the button stays grey until the page is reloaded.

Notes: Happens every time. Does not happen if the field is filled correctly the first time.

HSI-203

Mini test plan

practice

A one-page plan for testing Petal's "add a plant" feature before release.

Open test plan

Scope: Adding a plant with a name, photo, and watering schedule.

Out of scope: Notifications, user accounts, payments.

Approach

  • Manual functional testing of each field
  • Boundary checks (very long names, large photos, no photo)
  • Quick check on a phone-sized screen and a desktop browser

Ready to start when: the feature is deployed to a test build.

Done when: all planned cases are run and no high-severity bugs remain open.

HSI-204

Usability check

practice

A short review of Petal's home screen, looking at it the way a first-time user would.

Open usability notes

Works well: the "Add plant" button is easy to spot and the plant cards are clear.

Could improve

  • Watering reminders use only color to show urgency. Add a label or icon for color-blind users.
  • Tap targets on the filter chips are small on mobile.
  • The empty state says "Nothing here" but doesn't tell a new user what to do next.
  • Body text in the light-grey cards is hard to read against the background.

Suggested next step: test with three first-time users and note where they hesitate.
